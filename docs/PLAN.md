## Phase-by-phase approach

**Phase 0 — Foundations.** `apple/project.yml` with targets `Fengshui` (iOS), `FengshuiWatch` (watchOS single-target app, companion of `com.chevin.fengshui`), `FengshuiTests`, `FengshuiUITests`, `FengshuiWatchTests`; `FengshuiKit` local Swift package. `Config/Shared.xcconfig` includes optional `Local.xcconfig` (`#include?`) so simulator builds work without a team. Entitlements per spec (no Family Controls). Protocols + fakes skeleton. Spike A: link `Python.xcframework`, initialize the interpreter from a small C shim (`PythonBridge.c`), call `fengshui_engine.version()` and a SQLite read; `scripts/build_python_ios.sh` copies stdlib + engine + tzdata into the app bundle (`python/lib/...`). Spike C: Swift `RawCodec` (Compression `COMPRESSION_ZLIB` = raw DEFLATE), Python `fengshui_engine.raw`, vectors in `fixtures/raw/` generated by a Swift test tool and checked in.

**Phase 1 — Database + HealthKit.** Schema v1 as one SQL file `engine/fengshui_engine/schema_v1.sql` that is also bundled into FengshuiKit as a resource, so Swift and Python create byte-identical schemas. GRDB migrator (Swift) and `fengshui_engine.db` (Python) both apply it and check `schema_version`. `HealthStore` protocol; `HealthSync` does anchored backfill (5,000/txn, anchors per batch) and incremental with deletions. Type catalog built programmatically from the HealthKit identifier list; a generated `fixtures/hk_identifiers_ios26.txt` (from SDK headers, filtered to `ios(≤26)`) drives the label-mapping test. Observer queries + background delivery, with launch / `BGAppRefreshTask` fallback. Task B importer `scripts/import_health_export.py`.

**Phase 2 — Context.** `LocationProvider` protocol over `CLLocationManager` (visits, significant change) and `CLMonitor` (geofences, iOS 17+). Visit → place matching in Swift (nearest within radius); Python `place_suggestions`. `MotionHistory` protocol over `CMMotionActivityManager`. Places onboarding with MapKit pin drop.

**Phase 3 — Watch.** `SensorRecorder`, `DeviceMotionSource`, `AltimeterSource`, `HeadingSource`, `BatteryMonitor`, `WatchTransport` protocols. Tier 1 re-arm (12 h) + harvest watermark; tier 2 snapshot inside the refresh task with a deadline; tier 3 `HKWorkoutSession` (`.other`). Hourly container format `FSC1` (JSON index + concatenated chunks). `WCSession.transferFile` + `transferUserInfo` ack; delete on ack. Phone importer upserts on `(minute_id, sensor, tier)`. Complication via **ClockKit inside the watch app** (see DECISIONS D-07).

**Phase 4 — Engine.** Pure-Python tasks `features`, `activity`, `wind_down`, `wind_down_outcome`, `place_suggestions`, all constants in `config.py`. Synthetic generator `engine/tests/synth.py` writes `fixtures/scenarios/<name>.json`; Swift fakes read the same files. Swift `EngineRunner` actor runs the embedded engine in BG tasks. Real-data check against the Desktop DB.

**Phase 5 — Notifications.** `NotificationCenter` protocol; `WindDownScheduler` reacts to new/superseded plans (`wind_down_<night_of>` calendar trigger); Home-region rule; `notifications_log`; debug screen.

**Phase 6 — Server.** FastAPI app sharing `schema_v1.sql` + `devices` table; bearer auth; `/health`, `/sync`, `/raw/archive`, `/raw`, `/compute`, `/diagnostics`; Bonjour via `zeroconf`; `scripts/run_server.sh`, optional launchd plist.

**Phase 7 — Claude.** `AnthropicClient` protocol (URLSession impl + mock); tool implementations as read-only queries over a SQLite connection opened read-only, with an allowlist of tables (raw tables absent). Tool loop with round and size caps, `ai_log`. Preset questions + scheduler. Model names verified against Anthropic's current docs before coding.

**Phase 8 — Hardening.** Retries/backoff, DB export via `ShareLink`, Diagnostics + upload, privacy review, README, `FINAL_REPORT.md`, `DEVICE_TEST_CHECKLIST.md`.

## Parts of the spec that need an alternative (details in DECISIONS.md)

1. **GitHub** — the owner deferred it; branches/tags are kept locally and pushed later.
2. **Homebrew** not present → repo-local tool binaries (D-01).
3. **Complication** — a WidgetKit complication needs a widget-extension App ID, which breaks the "exactly two App IDs" rule on a free account. Use the (deprecated but present) ClockKit API inside the watch app; WidgetKit later with the paid account (D-07).
4. **Location background mode** — visit monitoring, significant-change and `CLMonitor` relaunch the app without the `location` background mode, so it is **not** enabled (spec allows "only if required") (D-08).
5. **watchOS 10 simulator** — Xcode 27 may not offer a watchOS 10 runtime; if not, watchOS tests run on the oldest available runtime and the watchOS-10-only behaviour is covered in the device test (D-09).
6. **NumPy** — not used; pure Python everywhere (D-05).
7. **Screen Time** — deferred behind `FENGSHUI_PAID_ACCOUNT`, per spec 1a.
